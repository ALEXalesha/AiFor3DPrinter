# AiForPrinter

**Нейросеть смотрит в камеру Elegoo Centauri Carbon во время печати и замечает брак: спагетти, отрыв детали от стола, ком пластика на сопле, печать «в воздух» без пластика. Тревога приходит в Telegram фотографией с тепловой картой «где брак» и двумя кнопками: «⏸ Пауза» и «✅ Всё нормально». Печать программа не останавливает никогда, а паузу без человека ставит только если это явно включить.**

## Что это и почему так

Камера в принтере есть, бот n8n с пультом в Telegram тоже есть (`camera_server.py` на порту 8099 отдаёт снимок, статус, паузу). Не хватало глаз: печать на 9 часов уходит в спагетти на первом часу, а замечается утром. Эта программа - глаза, но не руки:

| | |
| --- | --- |
| Когда смотрит | только при «Статус: печатает» (код 13 Centauri). Нагрев, калибровка, пауза - камера не трогается: стол пустой, тревоги там были бы ложными |
| Как часто | снимок раз в 15 с (5-300, настраивается) |
| Когда тревожит | 3 снимка из 4 последних - брак с уверенностью от 0.7; потом 10 минут тишины. Один кадр с бликом не будит. После «✅ Всё нормально» этот вид брака молчит до конца печати |
| Что присылает | фото с тепловой картой и рамкой вокруг самого «горячего» места, вид брака, уверенность, файл и слой |
| Что делает сам | ничего. Пауза - кнопкой человека. Автопауза есть, но выключена, пока цифры ложных тревог не станут хорошими |
| Остановка печати | никогда. В клиенте camera_server такого запроса нет, это проверяют законы и мутации |
| Где работает сеть | onnxruntime на процессоре, 2 потока, ~5 мс на кадр; PyTorch нужен только для обучения |

## Безопасность принтера: как устроено «никогда не stopprint»

Клиент (`watcher/camera_client.py`) знает ровно три пути - `/snap`, `/status`, `/pause` - в замороженном наборе. Любой другой путь отказывается до сети.

Нашлась и неочевидная дыра. camera_server разбирает путь как `self.path.split("?")[0]`. Если бы в настройках стоял адрес `http://127.0.0.1:8099/stopprint?x=`, то запрос снимка ушёл бы как `/stopprint?x=/snap` - и сервер остановил бы печать. Поэтому адрес camera_server принимается только в виде `http://хост:порт`: без пути, `?запроса`, `#якоря` и логина. Закон в `tests/test_never_stop.py` перебирает сотни адресов и путей и проверяет, что сервер в любом случае услышит только разрешённый путь.

Ещё законы: служба на поддельном camera_server прогоняется по случайным последовательностям статусов, сбоев и ответов сети, с автопаузой и без. Ни одного `/stopprint`; без автопаузы - ни одного `/pause`. Отдельная проверка разбирает весь код продукта (AST) и не находит ни строки, ни имени со `stopprint`.

Автопауза включена, только если в `config.json` стоит ровно `true` (не `"true"`, не `1`), а в окне - только после подтверждения.

`tools/mutate.py` ломает эти правила в копии кода (17 поломок: разрешить stopprint, пропустить `?` в адресе, заменить паузу остановкой, включить автопаузу по умолчанию, тревога по одному кадру, разбиение по кадрам...) и проверяет, что падает нужная проверка. С первого раза выжили две: служба смотрела бы и во время нагрева, и разбиение «по случаю» проходило проверку. Обе закрыты новыми проверками, сейчас 17 из 17. Адрес camera_server защищён двумя слоями (отказ и пересборка адреса из хоста и порта), и каждый слой ловит своя проверка.

## Модель

MobileNetV3-Large (torchvision, BSD-3, предобучена на ImageNet), дообучена на видеокарте (RTX 5060 Ti). Голова - свёртка 1x1 по признакам и среднее: тогда карта каждого вида - это Grad-CAM для этой головы, и она выходит из ONNX вторым выходом. Службе не нужен PyTorch даже для тепловой карты.

Полный паспорт - [model/PASSPORT.md](model/PASSPORT.md). Главная цифра - **ложные тревоги на час нормальной печати**: **0.41 в час** (18 тревог за 43.8 ч нормальной печати, 23 тестовые печати). Если на каждую ложную тревогу нажимать «✅ Всё нормально» - служба тогда глушит этот вид брака до конца печати - **0.11 в час** (5 тревог). Все 18 пришлись на три печати из 23: коробка Mario с россыпью деталей, дракон на тонких ножках, X-образные стойки.

Как считается: тестовые печати - те, чьих моделей (не только кадров) сеть не видела ни при обучении, ни при выборе чекпойнта. Таймлапс Centauri - кадр на слой, а служба смотрит раз в 15 с, поэтому каждый кадр «держится» всё время своего слоя. Соседние снимки службы тогда - один и тот же кадр, и ошибка одного кадра повторяется 3-4 раза подряд. Это худший случай для правила «3 из 4», живые снимки соседних моментов различаются сильнее.

| Вид | Точность | Полнота | Замечен при пороге 0.7 | Замечен за 5 мин (медиана) |
| --- | ---: | ---: | ---: | ---: |
| спагетти | 72.8% | 90.3% | 87.2% | 91% (40 с) |
| отрыв от стола | 71.5% | 91.9% | 88.6% | 74% (1 мин 10 с) |
| ком на сопле | 97.8% | 96.7% | 95.3% | 91% (38 с) |
| нет пластика | 100.0% | 98.8% | 96.4% | 78% (39 с) |

Настоящий нормальный кадр принят за брак в 8.1% случаев (из 2 511), но почти все такие кадры - те же три необычные печати: правило «3 из 4» и тишина после тревоги превращают их в 18 тревог, а не в сотни. Порог 0.95 вместо 0.7 даёт 0.18 тревоги в час ценой полноты - таблица перебора в паспорте.

На 160 настоящих кадрах спагетти из набора SKZ (другой принтер, камера сверху) брак замечен на всех. Цифра слабая: в обучении каждый кадр SKZ - спагетти, и сеть могла выучить «чужая камера = спагетти».

### Первая версия ошибалась на нескольких деталях сразу

Первая обученная сеть давала **0.87 ложной тревоги в час** (38 за 43.8 ч). 34 из 38 пришлись на три печати: красная коробка Mario с россыпью деталей вокруг, дракон на тонких ножках и X-образные стойки. Сеть выучила «много цветного на столе = спагетти»: в обучении искусственные спагетти - это и есть цветное, разбросанное по столу, а нормальные кадры почти всегда с одной деталью.

Лечение - в `dataset/synth.py::extra_parts`: на нормальные кадры добавляются 1-4 копии печатаемой детали, мельче и в другом месте, стоящие ровно (в «отрыве» деталь лежит на боку). Такие кадры остаются нормой. Плюс норма - 55% эпохи вместо 40%. Стало 0.41 в час: те же три печати, но вдвое меньше тревог. Остаток - вопрос данных: таких деталей в обучении нет, их принесут кнопки «Всё нормально» за неделю наблюдений. До тех пор работает заглушка: «Всё нормально» глушит этот вид брака до конца печати, и необычная деталь стоит одной тревоги, а не шести за час.

### Что эти цифры не говорят

Брак в проверке - искусственный, нарисованный поверх настоящих кадров тех же тестовых печатей. Поэтому точность по видам брака оптимистична. Настоящих кадров брака с этой камеры нет совсем; настоящие спагетти есть только с другой камеры (набор SKZ, вид сверху). Нормальные кадры - настоящие, поэтому ложные тревоги в час - честная цифра, но на таймлапсах: в живом снимке голова ездит и выдержка другая. Живой снимок во время печати вазы обе версии сети оценили как норму (0.96 и 0.94) - это два кадра, не статистика. Поэтому впереди неделя наблюдений, и автопауза до неё выключена.

### Как нарисован брак

У камеры Centauri голова печатает в одной горизонтальной плоскости, а стол опускается на слой. Поэтому верх растущей детали на кадре всегда у «линии сопла» (~y=165 из 360), и это главное, что сеть должна видеть:

- **спагетти** - путаные нити цвета пластика (случайные блуждания с тенью и бликом) и куски настоящих спагетти SKZ, перекрашенные в цвет пластика;
- **ком на сопле** - неровный ком с бликом там, где сопло касается детали;
- **отрыв** - деталь вырезана со своего места (`cv2.inpaint`) и положена рядом на бок, иногда с нитями;
- **нет пластика** - стол «уехал» вниз, а деталь не выросла: щель между линией сопла и верхом детали, иногда висящие нити.

Чтобы сеть не училась на следах подделки (размытые пятна заливки), такие же заливки и вставки делаются и на нормальных кадрах.

## Обмен с ботом n8n

Токен Telegram живёт только в n8n, служба его не знает. Обмен - через папку `n8n_pc\run\aifp`, как у ответа Claude в боте:

```
служба:  outbox/<id>.jpg   кадр с тепловой картой (пишется первым)
         outbox/<id>.json  тревога; появился json = можно отправлять
бот:     outbox/<id>.json -> .sent ДО отправки (не больше одного раза), потом фото + кнопки
кнопки:  inbox/<id>.pause  «⏸ Пауза» (бот сам зовёт :8099/pause)
         inbox/<id>.ok     «✅ Всё нормально» -> служба кладёт кадр в feedback/normal (в обучение)
```

`id` - только `ГГГГММДД-ччммсс-xxxx`: из него строится имя файла, чужое имя уходит в `inbox/bad`.

## Запуск

```powershell
uv venv -p 3.13 .venv
uv pip install -r requirements-dev.txt
.venv\Scripts\python main.py ui        # окно
.venv\Scripts\python main.py watch     # служба (или tools\watch.cmd)
wscript tools\watch-hidden.vbs           # служба без окна (журнал: %LOCALAPPDATA%\AiForPrinter\watcher.log)
powershell -File tools\stop-watch.ps1   # остановить службу (camera_server и n8n не трогает)
.venv\Scripts\python main.py check     # один снимок сейчас и оценка (только чтение)
```

Данные службы - в `%LOCALAPPDATA%\AiForPrinter`: `config.json`, `watcher.log`, `state.json`, кадры тревог `alerts\`, кадры кнопки «Всё нормально» `feedback\normal\`.

Окно: живой снимок с тепловой картой, уверенность по видам, график брака за печать с линией порога, история тревог с ответами кнопок, настройки. Пять тем Paint (Стеклянная, Строгая, Светлая, Ночная, Тёплая), русский и английский, место и размер окна запоминаются.

### Обучение

```powershell
uv pip install -r requirements-train.txt
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu130
python -m dataset.frames <папка таймлапсов>    # кадры по печатям
python -m dataset.skz                          # часть набора SKZ (~1 ГБ скачивания)
python -m dataset.build                        # подделки брака + index.csv
python -m model.train --trial                  # замер скорости и оценка времени
python -m model.train --epochs 16              # ~15 мин на RTX 5060 Ti
python -m model.export <runs\...\best.pt>      # -> model\aifp.onnx
python -m model.evaluate                       # -> model\PASSPORT.md
python -m dataset.label_tool                   # ручная разметка кадров тревог
```

Замер перед полным обучением: 744 кадра/с, эпоха ~0.9 мин, 16 эпох ~15 мин. Потоки процессора ограничены (4 на загрузку, 4 на torch): на ПК работают другие программы.
